# プロジェクト目的・設計原則

## 目的

「としくんSNS制作ライン」は、YouTube長尺動画の校正済み原稿を唯一の情報源として、SNS別のドラフトを半自動生成する仕組みです。人間が担うのは長尺原稿の最終校正、撮影、SNSドラフトの最終確認、実際の投稿です。

## MVPの境界

MVPは「原稿入力 → SNS案生成 → 自動品質チェック → 確認待ち整理」までです。投稿API、予約投稿、Google Drive連携、Place T、としくん知識との連携は含めません。外部システム連携は、MVP運用で品質基準が固まった後に追加します。

## 絶対に守る品質原則

発信者は、科学的根拠を重視する現役の化粧品研究員「としくん」です。

1. 原稿にない事実を追加しない。
2. 研究結果、第三者の主張、としくん本人の見解を区別する。
3. ヒト研究、動物研究、in vitroを混同しない。
4. 相関を因果として表現しない。
5. 統計的有意差を臨床的に大きな効果と読み替えない。
6. 医薬品的な治療・予防・改善の断定を避ける。
7. 研究の限界、対象、条件を結論に必要な範囲で残す。
8. 数値、単位、濃度、人数、期間を変更しない。
9. 不明な情報を補完・創作しない。不明なら明示するか使わない。
10. 各ドラフトに、判断可能な短い根拠抜粋を付ける。

自動チェックは誤りを完全には検出できません。警告がゼロでも人間の最終確認は必須です。

## 媒体設計

- **Shorts:** 冒頭のフック、1本1知識、短時間で理解できる台本。正確性より煽りを優先しない。
- **X:** 短く専門性があり、独立して理解できる投稿。同じ主張の焼き直しを避ける。
- **Instagram:** 保存・再参照しやすい情報設計。複数項目はカルーセルにする。
- **LINE:** 既存視聴者・顧客への自然な案内。過剰な販促にしない。
- **YouTubeタイトル／サムネ:** 原稿との整合性を優先し、誇張や重要条件の脱落を避ける。

## 設計判断

- 原稿をAPIへ送るため、機密情報・個人情報を投入しない。
- 生成結果をJSONで保存し、再検査・将来の連携を可能にする。
- 読みやすいMarkdownも生成し、レビュー担当がJSONを編集する必要をなくす。
- 原稿スナップショット、設定、時刻、モデル名を残し、追跡可能にする。
- 生成件数とプロンプトはコードから分離した設定で管理する。
- 自動投稿機能を設けず、成果物の状態は常に `確認待ち` とする。
