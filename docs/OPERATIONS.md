# 運用手順

## 人間とシステムの責任分界

1. 人間が企画・調査し、YouTube長尺原稿を最終校正する。
2. 人間が撮影する。
3. 校正済み原稿だけをCLIに入力する。
4. システムが媒体別ドラフトを生成し、自動チェックする。
5. 人間が `review.md` と `quality-report.json` を照合する。
6. 人間が必要な修正を行い、最終的に各媒体へ投稿する。

システムからSNSへ投稿する工程はありません。

## 入力原稿の推奨形式

Markdownで、タイトル、本文、研究の種類、対象人数、期間、数値、出典、限界、本人の見解を可能な限り明記します。研究結果と見解は見出しやラベルで分けてください。曖昧な原稿をAIが正確に補うことはできません。

## レビュー・チェックリスト

- [ ] すべての主張が原稿の `evidence` で確認できる
- [ ] 根拠抜粋が文脈を歪めていない
- [ ] 数値・単位・人数・期間・濃度が一致する
- [ ] ヒト／動物／in vitroの種別が維持されている
- [ ] 相関を因果にしていない
- [ ] 統計的有意差を効果の大きさと混同していない
- [ ] 研究の対象・限界・条件が必要に応じて残っている
- [ ] 治療、予防、治癒、必ず効く等の断定がない
- [ ] Shortsは1本1知識で、フックと本文が一致する
- [ ] X 10本が別の論点を扱っている
- [ ] Instagramが保存しやすく、各スライドが読みやすい
- [ ] LINEが既存視聴者向けの自然な文章である
- [ ] タイトルとサムネが動画内容を誇張していない
- [ ] 投稿先の最新規約と表示を人間が確認した

## 警告の扱い

`error` は件数・構造などの契約違反で、原則として再生成します。`warning` は人間が原稿と照合し、問題がない理由を確認してから利用します。単純な文字列検査のため、誤検知・見逃しの両方があります。

成果物は上書きせずジョブ単位で保存し、採用・却下・修正理由は将来の改善材料として別途記録してください。APIキーを原稿、成果物、Git、スクリーンショットへ含めないでください。
